카카오톡 봇

# 게이트웨이

봇 서버가 카카오톡 서버에 **웹소켓으로 상시 연결**해 사용자 발화를 수신하는 방식입니다. [웹훅](웹훅.md) 방식과의 차이는 [이벤트 수신](이해하기.md#이벤트%20수신)을 참고합니다.

웹소켓 연결, 이벤트 수신, 답장까지 전체 흐름은 [에코봇으로 테스트](#에코봇으로%20테스트)해 바로 확인할 수 있습니다. 상세 흐름은 [웹소켓 프로토콜 흐름](#웹소켓%20프로토콜%20흐름)을, 필드 명세는 [프로토콜 레퍼런스](#프로토콜%20레퍼런스)를 참고합니다.

## 시작하기 전에

게이트웨이로 이벤트를 수신하려면 아래 사항을 준비해야 합니다.

- [앱 관리 페이지](https://developers.kakao.com/console/app)에서 [봇을 생성](설정하기.md#생성필수)합니다.
- 웹소켓 연결을 유지할 수 있는 상시 실행 환경(워커, 데몬, 컨테이너 등)을 준비합니다.
- [웹훅 URL](설정하기.md#웹훅)을 등록한 경우 게이트웨이 방식은 사용할 수 없습니다. 웹훅이 등록되어 있다면 웹훅을 삭제합니다.

## 웹소켓 프로토콜 흐름

아래는 게이트웨이 웹소켓을 연결하고 이벤트를 받기까지의 구현 순서입니다. 각 Opcode의 필드와 예제는 [프로토콜 레퍼런스](#프로토콜%20레퍼런스)를 참고합니다. 운영 환경에서는 [재연결](#재연결)까지 구현합니다.

웹소켓 프로토콜 흐름![](https://developers.kakao.com/docs/_next/image?url=%2Fimg%2Fbot_gateway_websocket_ko.png&w=2040&q=75)

1. **봇**이 `wss://bot-gateway.kakao.com/gateway`로 웹소켓을 연결합니다. ([연결 및 인증](#연결%20및%20인증))
2. **카카오톡 서버**가 [`HELLO`](#HELLO)(op=10)를 보냅니다.
3. **봇**이 [`IDENTIFY`](#IDENTIFY)(op=2)로 인증합니다.
4. **카카오톡 서버**가 [`READY`](#READY)(op=3)를 보냅니다.
5. **봇**이 [`HEARTBEAT`](#HEARTBEAT)(op=1)를 주기적으로 보냅니다. ([연결 유지](#연결%20유지))
6. **카카오톡 서버**가 [`HEARTBEAT_ACK`](#HEARTBEAT)(op=11)로 응답합니다.
7. **카카오톡 서버**가 이벤트가 있으면 [`DISPATCH`](#DISPATCH)(op=0)를 보냅니다. ([채팅방 이벤트 수신](#채팅방%20이벤트%20수신))
8. **카카오톡 서버**가 이후에도 [`DISPATCH`](#DISPATCH)를 계속 전달합니다.

5~8은 `READY` 이후 **병행**됩니다. 재연결 시 **봇**은 [`RESUME`](#RESUME)(op=6)을 보낼 수 있습니다. 시점은 [재연결](#재연결)을 참고합니다.

### 연결 및 인증

1. `wss://bot-gateway.kakao.com/gateway`로 웹소켓을 연결합니다.
2. [`HELLO`](#HELLO)를 수신하고 `d.heartbeat_interval`을 저장합니다.
3. [`IDENTIFY`](#IDENTIFY)로 인증합니다. `d.token`에 [봇 인증 토큰](설정하기.md#인증%20토큰)을 넣습니다. `READY`를 받기 전까지 `DISPATCH`는 전달되지 않습니다.
4. [`READY`](#READY)의 `d.session_id`를 저장합니다.
5. 이후 [연결 유지](#연결%20유지)와 [채팅방 이벤트 수신](#채팅방%20이벤트%20수신)을 **병행**합니다.

재연결 시에는 `IDENTIFY` 대신 [`RESUME`](#RESUME)을 보낼 수 있습니다. 선택 기준은 [재연결](#재연결)을 참고합니다.

### 연결 유지

`HELLO`의 `heartbeat_interval`(기본 41250 ms)보다 약간 짧게 [`HEARTBEAT`](#HEARTBEAT)를 반복 전송합니다.

- 서버는 [`HEARTBEAT_ACK`](#HEARTBEAT)로 응답합니다. 별도 처리가 필요 없습니다.
- 마지막 `HEARTBEAT` 이후 **90초** 이상 없으면 서버가 `close(4009)`로 연결을 끊습니다.
- 클라이언트에서도 `HEARTBEAT_ACK` 누락을 감지해 재연결하는 것을 권장합니다.

### 채팅방 이벤트 수신

인증이 끝난 뒤 카카오톡 서버는 [`DISPATCH`](#DISPATCH)로 채팅방 이벤트를 전달합니다.

1. `op`가 `0`인지 확인합니다.
2. `s`를 **매번 저장**합니다. ([재연결](#재연결) 시 `RESUME`의 `d.seq`로 사용)
3. `t`로 분기하고 `d`를 처리합니다. 필드 명세는 [DISPATCH](#DISPATCH)를 참고합니다.
4. `callbackToken`이 있으면 [메시지 응답](#메시지%20응답)으로 이어갑니다.

#### 채팅방 이벤트 종류

|이벤트 (`t`)|설명|
|---|---|
|[`MESSAGE_CREATE`](#MESSAGE_CREATE)|사용자가 봇 채널에 메시지를 전송할 때|
|[`ENTRANCE`](#ENTRANCE)|봇이 채팅방에 입장했을 때|
|[`CHAT_JOIN`](#CHAT_JOIN)|사용자가 채팅방에 입장했을 때|
|[`LEAVE`](#LEAVE)|봇이 채팅방에서 퇴장했을 때|
|[`AD_REWARD`](#AD_REWARD)|사용자가 광고를 시청해 리워드를 받았을 때|

### 메시지 응답

카카오톡 서버는 메시지를 **전달만** 합니다. 답장은 웹소켓이 아닌 [메시지 콜백 API](REST%20API.md#메시지%20콜백)로 보냅니다. ([메시지 전송 흐름](이해하기.md#메시지%20전송) 참고)

1. [`DISPATCH`](#DISPATCH)에서 `d.callbackToken`을 추출합니다. (참고: [콜백 토큰](#콜백%20토큰))
2. 응답 내용을 [SkillResponse](REST%20API.md#SkillResponse) 형식으로 구성합니다.
3. 콜백 토큰을 헤더에 넣어 [메시지 콜백 API](REST%20API.md#메시지%20콜백)를 호출합니다.

#### 콜백 토큰

`callbackToken`은 [메시지 콜백 API](REST%20API.md#메시지%20콜백) 인증에 쓰는 **일회성** 토큰입니다. [`MESSAGE_CREATE`](#MESSAGE_CREATE), [`ENTRANCE`](#ENTRANCE), [`CHAT_JOIN`](#CHAT_JOIN), [`AD_REWARD`](#AD_REWARD)의 `d`에 포함되며, 없으면 답장할 수 없으므로 해당 이벤트는 건너뜁니다.

**콜백 토큰 만료 시간**

만료 시간은 5분입니다. 사용자의 발화에 **5분 이내** 응답해야 합니다.

callback_token = payload["d"].get("callbackToken")

if not callback_token:

    return  # 답장 불가 — 건너뜀

### 재연결

게이트웨이 방식은 봇이 **직접** 연결을 복구해야 합니다. `READY`의 `session_id`와 `DISPATCH`의 `s`를 저장해 두고, 연결이 끊기면 아래 기준으로 `RESUME` 또는 새 `IDENTIFY`를 선택합니다.

웹소켓 RESUME 흐름![](https://developers.kakao.com/docs/_next/image?url=%2Fimg%2Fbot_gateway_websocket_resume_ko.png&w=2040&q=75)

|[Close code](#Close%20code)|상황|봇이 할 일|
|---|---|---|
|`1001`|서버 재시작|즉시 [`RESUME`](#RESUME). 실패 시 새 [`IDENTIFY`](#IDENTIFY)|
|-|네트워크만 끊김|`RESUME` 먼저 시도, 실패 시 새 `IDENTIFY`  <br>`session_id`와 마지막 `s`가 있고 세션이 유효 [`RESUME`](#RESUME)|
|`4009`|세션 만료 (또는 세션 없음)|`session_id` 초기화 후 새 [`IDENTIFY`](#IDENTIFY)|
|`4001`|인증 실패|종료. [봇 인증 토큰](설정하기.md#인증%20토큰) 확인|
|`4003`|유효하지 않은 페이로드|종료. 전송 데이터 점검|
|`4004`|다른 연결로 대체됨|종료. 동일 봇 중복 연결 여부 확인|

Close code 목록은 [Close code](#Close%20code)를 참고합니다.

#### 재연결 주의 사항

- **이벤트 버퍼**: 연결별로 최근 **100개** 이벤트만 보관합니다. 봇이 오랫동안 중단된 뒤 `RESUME`하면 그 사이 이벤트는 복구되지 않을 수 있습니다.
- **재시도 간격**: 연결이 반복해서 끊기면 지수 백오프(1초 → 2초 → 4초 → … 최대 30초)를 적용합니다.

## 에코봇으로 테스트

아래 에코봇은 사용자 메시지를 받아 `echo:` 형태로 되돌려 보내는 최소 예제입니다. `MESSAGE_CREATE`만 처리하며, [웹소켓 프로토콜 흐름](#웹소켓%20프로토콜%20흐름)과 같은 순서로 동작하는지 확인할 수 있습니다. [재연결](#재연결)은 다루지 않습니다.

##### 개발 환경 설정

- **Python** 3.11 이상
- **패키지 매니저**: [uv](https://docs.astral.sh/uv/)
- **라이브러리**: `httpx`, `websockets`

### 1. 환경 변수 설정

[앱 관리 페이지](https://developers.kakao.com/console/app)의 [제품 설정] > [카카오톡 봇] > [봇]에서 [봇 인증 토큰](설정하기.md#인증%20토큰)을 확인한 뒤, 아래 환경 변수에 넣습니다.

export BOT_TOKEN="${봇 인증 토큰}"

### 2. 파일 생성

작업 디렉터리를 만들고 `gateway_echo_bot.py` 파일을 생성해 아래 예제 코드를 저장합니다.

mkdir -p ~/bot-test

핸드셰이크(`HELLO` → `IDENTIFY` → `READY`)로 인증한 뒤 `DISPATCH` 이벤트를 수신하는 에코봇 예제입니다.

# /// script

# requires-python = ">=3.11"

# dependencies = [

#     "httpx>=0.27",

#     "websockets>=15.0",

# ]

# ///

import asyncio

import json

import logging

import os

import sys

import httpx

import websockets

from websockets.exceptions import ConnectionClosed

logging.basicConfig(level=logging.INFO, format="%(asctime)s %(levelname)s %(message)s")

log = logging.getLogger("echobot")

# ── Config ───────────────────────────────────────────────────────────

BOT_TOKEN = os.getenv("BOT_TOKEN")

KAKAO_GW_URL = "wss://bot-gateway.kakao.com/gateway"

KAKAO_API_URL = "https://kapi.kakao.com"

# ── Opcodes ──────────────────────────────────────────────────────────

OP_DISPATCH = 0

OP_HEARTBEAT = 1

OP_IDENTIFY = 2

OP_READY = 3

OP_RESUME = 6

OP_HELLO = 10

OP_HEARTBEAT_ACK = 11

# ── Close Code ───────────────────────────────────────────────────────

CLOSE_SERVER_RESTART = 1001   # Graceful shutdown → RESUME

CLOSE_AUTH_FAILED = 4001      # token 오류 → 중단

CLOSE_INVALID_PAYLOAD = 4003  # 프로토콜 버그 → 중단

CLOSE_REPLACED = 4004         # 중복 연결로 대체됨 → 중단

CLOSE_SESSION_TIMEOUT = 4009  # 세션 만료 → 새 IDENTIFY

RECONNECT_BACKOFF_SEC = 3.0

# ── 메시지 처리 ──────────────────────────────────────────────────────

async def on_message(d: dict) -> None:

    """MESSAGE_CREATE 이벤트를 받아 받은 내용을 그대로 callback으로 돌려준다."""

    content = d.get("content", "")

    callback_token = d.get("callbackToken", "")

    log.info("MESSAGE_CREATE — content=%s", content[:100])

    if not callback_token:

        log.error("callbackToken 누락 — skip")

        return

    await send_callback(callback_token, content)

# ── 봇 callback ──────────────────────────────────────────

async def send_callback(callback_token: str, text: str) -> None:

    """봇 callback 엔드포인트로 카카오 스킬 응답(simpleText)을 전송한다."""

    url = f"{KAKAO_API_URL}/v1/bot/callback"

    body = {

        "skillResponse": {

            "version": "2.0",

            "template": {"outputs": [

                    {"simpleText": {"text": f"echo: {text}"}},

                ]

            },

        },

    }

    headers = {

        "X-Bot-Callback-Token": callback_token,

        "Authorization": f"KakaoAK {BOT_TOKEN}"

    }

    async with httpx.AsyncClient() as client:

        resp = await client.post(url, json=body, headers=headers)

    if resp.status_code != 200:

        log.error("callback failed — %d %s", resp.status_code, resp.text)

# ── 세션 상태 ────────────────────────────────────────────────────────

class Session:

    """RESUME에 필요한 session_id와 마지막으로 받은 시퀀스(seq)를 보관한다."""

    def __init__(self) -> None:

        self.session_id: str | None = None

        self.last_seq: int = 0

    def can_resume(self) -> bool:

        return self.session_id is not None

    def reset(self) -> None:

        self.session_id = None

        self.last_seq = 0

# ── WebSocket 게이트웨이 ─────────────────────────────────────────────

async def gateway_loop(session: Session) -> None:

    """게이트웨이에 한 번 연결해 핸드셰이크 후 heartbeat·수신 루프를 동시에 돈다."""

    log.info("connecting to %s", KAKAO_GW_URL)

    async with websockets.connect(KAKAO_GW_URL) as ws:

        # 1. HELLO 수신 — heartbeat_interval 확인

        hello = json.loads(await ws.recv())

        heartbeat_interval = hello["d"]["heartbeat_interval"] / 1000.0

        if session.can_resume():

            # 재연결: RESUME으로 세션 복구

            log.info("RESUME — session=%s, seq=%d", session.session_id, session.last_seq)

            await ws.send(json.dumps({"op": OP_RESUME, "d": {

                "token": BOT_TOKEN,

                "session_id": session.session_id,

                "seq": session.last_seq,

            }}))

        else:

            # 최초 연결: IDENTIFY → READY

            await ws.send(json.dumps({"op": OP_IDENTIFY, "d": {

                "token": BOT_TOKEN,

            }}))

            ready = json.loads(await ws.recv())

            session.session_id = ready["d"]["session_id"]

            session.last_seq = 0

            log.info("READY — bot id=%s, session=%s",

                     ready["d"]["bot"]["id"], session.session_id)

        # 2. heartbeat + 이벤트 수신을 동시에 실행

        await asyncio.gather(

            _heartbeat(ws, heartbeat_interval),

            _receive(ws, session),

        )

async def _heartbeat(ws, interval: float) -> None:

    while True:

        await asyncio.sleep(interval)

        await ws.send(json.dumps({"op": OP_HEARTBEAT}))

async def _receive(ws, session: Session) -> None:

    async for raw in ws:

        payload = json.loads(raw)

        if payload.get("s") is not None:

            session.last_seq = payload["s"]

        if payload.get("op") == OP_DISPATCH and payload.get("t") == "MESSAGE_CREATE":

            await on_message(payload["d"])

def _should_resume(code: int | None) -> bool:

    if code in (CLOSE_AUTH_FAILED, CLOSE_INVALID_PAYLOAD, CLOSE_REPLACED):

        log.error("close %s — 재연결 중단 (프로토콜/인증 오류)", code)

        raise SystemExit(1)

    if code == CLOSE_SESSION_TIMEOUT:

        return False

    return True

async def run(session: Session) -> None:

    while True:

        try:

            await gateway_loop(session)

        except ConnectionClosed as e:

            code = e.rcvd.code if e.rcvd else None

            reason = e.rcvd.reason if e.rcvd else ""

            log.warning("connection closed — code=%s reason=%s", code, reason)

            if not _should_resume(code):

                session.reset()

        except OSError as e:

            log.warning("connect failed — %s", e)

        log.info("reconnecting in %.1fs …", RECONNECT_BACKOFF_SEC)

        await asyncio.sleep(RECONNECT_BACKOFF_SEC)

async def main():

    if not BOT_TOKEN:

        log.error("BOT_TOKEN 환경변수를 설정하세요")

        sys.exit(1)

    log.info("echo bot starting — gateway=%s", KAKAO_GW_URL)

    await run(Session())

if __name__ == "__main__":

    try:

        asyncio.run(main())

    except KeyboardInterrupt:

        print("\n[echobot] stopped")

### 3. 실행 및 동작 확인

터미널에서 아래 명령으로 에코봇을 실행합니다.

uv run ~/bot-test/gateway_echo_bot.py

실행에 성공하면 아래와 같이 `READY` 로그가 출력됩니다. 터미널을 닫지 않은 상태에서 카카오톡 봇 채널로 메시지를 전송하면 `echo: \{원문\}` 형태로 답장이 전달됩니다.

2026-07-08 10:25:14,749 INFO READY — bot id=6a3e0dde54aeda47652b79c6, session=sess_ec0ad2ce

**연결 실패한 경우**

웹훅 URL이 등록돼 있으면 게이트웨이에 연결할 수 없습니다. [시작하기 전에](#시작하기%20전에)를 확인합니다.

## 프로토콜 레퍼런스

웹소켓 프로토콜의 프레임 형식, Opcode별 이벤트 페이로드, Close code를 설명합니다. **언제 보낼지**는 [웹소켓 프로토콜 흐름](#웹소켓%20프로토콜%20흐름)을 참고합니다.

모든 프레임은 JSON 형식입니다. 수신 후 `op` 값으로 분기합니다. `null` 필드는 직렬화 시 생략됩니다.

|필드|타입|설명|포함 여부|
|---|---|---|---|
|`op`|`Integer`|프레임 종류. [`Opcode`](#`Opcode`) 참고|O|
|`s`|`Integer`|시퀀스 번호. [`DISPATCH`](#DISPATCH)에만 포함. 연결마다 1부터 증가하며, 새 `IDENTIFY` 연결 시 1부터 다시 시작|X|
|`t`|`String`|이벤트 타입. [`DISPATCH`](#DISPATCH)에만 포함|X|
|`d`|`JSON`|Opcode별 데이터. [Opcode 상세](#Opcode%20상세) 참고|X|

{

  "op": 0,

  "s": 1,

  "t": "MESSAGE_CREATE",

  "d": { ... }

}

### `Opcode`

|`op`|이름|방향|설명|
|---|---|---|---|
|0|[`DISPATCH`](#DISPATCH)|카카오톡 서버 → 봇|이벤트 전달 (`s`, `t`, `d` 포함)|
|1|[`HEARTBEAT`](#HEARTBEAT)|봇 → 카카오톡 서버|연결 유지 ping|
|2|[`IDENTIFY`](#IDENTIFY)|봇 → 카카오톡 서버|최초 인증|
|3|[`READY`](#READY)|카카오톡 서버 → 봇|`IDENTIFY` 성공 응답|
|6|[`RESUME`](#RESUME)|봇 → 카카오톡 서버|세션 재개|
|10|[`HELLO`](#HELLO)|카카오톡 서버 → 봇|연결 직후 전송 (`heartbeat_interval`)|
|11|[`HEARTBEAT_ACK`](#HEARTBEAT)|카카오톡 서버 → 봇|`HEARTBEAT` 응답|

### Close code

웹소켓 연결 종료 시 게이트웨이가 클로즈 코드와 함께 연결을 닫습니다. 코드별 대응은 [재연결](#재연결)을 참고합니다.

|Code|의미|
|---|---|
|1001|서버 재시작 (Graceful shutdown)|
|4001|인증 실패 (토큰 누락 또는 오류)|
|4003|유효하지 않은 페이로드|
|4004|다른 연결로 대체됨 (중복 IDENTIFY)|
|4009|세션 만료|
